1. IAM — Identity and Access Management

Your basic understanding is correct.

What is IAM?

IAM controls who can access AWS resources and what actions they are allowed to perform.

For example:

Developer → can start/stop EC2
Support user → can view EC2 and logs
Administrator → can create, modify, and delete resources
Read-only user → can only view resources
IAM structure

A simple flow is:

IAM → User/Role → Permission → Policy → AWS Resource

For example:

IAM User
   ↓
Attach Policy
   ↓
AmazonEC2ReadOnlyAccess
   ↓
User can view EC2 resources
   ↓
Cannot start/stop/delete EC2
Important correction

You said:

"as per role required it provides access in which it has separate parameter to provide access as per role"

Better way to say it:

IAM provides authentication and authorization. IAM policies define which AWS resources a user or role can access and which actions they can perform.

2. IAM Policy

A policy is a JSON document that defines permissions.

For example, a policy could allow:

Action: ec2:StartInstances
Resource: specific EC2 instance
Effect: Allow

Or you can use AWS-managed policies such as:

AmazonEC2ReadOnlyAccess
AmazonS3ReadOnlyAccess
AmazonS3FullAccess

There are also custom policies that you create according to your organization's requirements.

Example

Suppose a support engineer should only be able to restart EC2 instances.

You can create a policy that allows:

ec2:StartInstances
ec2:StopInstances
ec2:RebootInstances

but doesn't allow:

ec2:TerminateInstances

This follows the least privilege principle — give users only the permissions they actually need.

3. ARN

You mentioned:

specify ARNs

Correct.

ARN = Amazon Resource Name

It uniquely identifies an AWS resource.

Example:

arn:aws:ec2:ap-south-1:123456789012:instance/i-0123456789abcdef

You can use an ARN in an IAM policy to specify which particular resource the permission applies to.

For example:

User → Start EC2
         ↓
Only EC2 Instance A

rather than allowing the user to start every EC2 instance.

4. EC2 vs S3

This is an important interview question.

EC2	S3
Elastic Compute Cloud	Simple Storage Service
Compute service	Object storage service
Used to run applications	Used to store files/objects
VM/server	Storage
Has CPU, RAM, OS	Doesn't provide a traditional VM/OS
Can install software	Stores objects such as files
Can run Linux/Windows	Stores images, backups, logs, documents, etc.
EBS can be attached	Objects are stored in buckets
Simple example

Suppose you have a website:

EC2
 ↓
Runs your application

And your website has images:

S3
 ↓
Stores website images

So:

EC2 is used for computing, while S3 is used for object storage.

8. Route Table

This is an important part that you should understand clearly.

A route table determines where network traffic should go.

For a public web subnet, you might have:

Destination       Target
0.0.0.0/0         Internet Gateway

Meaning:

Traffic destined for anywhere on the internet should go through the Internet Gateway.

Architecture:

                 Internet
                    |
                   IGW
                    |
              Route Table
             0.0.0.0/0 → IGW
                    |
               Web Subnet
                    |
                   EC2

The route table is then associated with the subnet.

So your statement:

"create web route table which is affiliated via web subnet via VPC"

is essentially correct.

Better interview wording:

I create a route table in the VPC, add the required routes, and associate the route table with the appropriate subnet. For a public subnet, I typically add a default route 0.0.0.0/0 pointing to the Internet Gateway.

10. VPC Peering

You mentioned VPC peering but haven't fully described it.

VPC Peering allows two VPCs to communicate with each other using private IP addresses.

For example:

VPC-A                         VPC-B
10.0.0.0/16                  20.0.0.0/16
   |                            |
Web EC2                      DB EC2
   \                            /
    \------ VPC Peering -------/

Suppose:

VPC-A → 10.0.0.0/16
VPC-B → 20.0.0.0/16

You create a peering connection and configure routes such as:

VPC-A Route Table

Destination       Target
20.0.0.0/16       VPC Peering Connection

And on VPC-B:

VPC-B Route Table

Destination       Target
10.0.0.0/16       VPC Peering Connection

Then resources in the two VPCs can communicate, assuming security groups/NACLs and other controls allow the traffic.

12. Interview answer — "Explain VPC"

You can answer:

VPC stands for Virtual Private Cloud. It is a logically isolated network in AWS where we deploy and manage resources such as EC2 instances. Within a VPC, we can create public and private subnets, configure route tables, Internet Gateways, NAT Gateways, security groups and network ACLs. For example, I can place web servers in a public subnet and databases in a private subnet. The public subnet can have a route to an Internet Gateway, while the database subnet remains private. If communication is required between two different VPCs, we can use VPC Peering and configure the appropriate routes in both VPCs.

One important correction to remember

Don't say:

"VPC creates the EC2 instance."

Say:

"We create a VPC and subnet, and then launch the EC2 instance into the selected subnet."

The VPC provides the networking environment; EC2 provides the compute instance.

Absolutely. Based on the IAM, EC2, S3, VPC, Subnets, Route Tables, Internet Gateway, and VPC Peering topics you are studying, here are interview-focused questions and answers.

IAM Interview Questions
1. What is IAM in AWS?

Answer:

IAM stands for Identity and Access Management. It is used to control authentication and authorization in AWS. IAM allows us to create users, groups, roles, and policies and define what actions they can perform on AWS resources.

2. What is an IAM policy?

Answer:

An IAM policy is a JSON document that defines permissions. It specifies what actions are allowed or denied, on which resources, and under what conditions.

Example:

Effect: Allow
Action: ec2:StartInstances
Resource: specific EC2 instance
3. What is the difference between authentication and authorization?

Answer:

Authentication verifies who the user is, while authorization determines what that authenticated user is allowed to do.

Example:

Authentication → Who are you?
Authorization  → What are you allowed to access?
4. What is the principle of least privilege?

Answer:

Least privilege means providing a user or application only the permissions required to perform its job and avoiding unnecessary permissions.

For example, if a support engineer only needs to restart EC2 instances, I would not provide full administrator access.

5. What is an ARN?

Answer:

ARN stands for Amazon Resource Name. It uniquely identifies an AWS resource. We can use ARNs in IAM policies to specify exactly which AWS resource the policy applies to.

Example:

arn:aws:ec2:ap-south-1:123456789012:instance/i-123456789
6. What is the difference between AWS-managed and customer-managed policies?

Answer:

AWS-managed policies are predefined and maintained by AWS. Customer-managed policies are created and managed by us according to our organization's requirements.

7. What is an IAM role?

Answer:

An IAM role provides temporary permissions to AWS resources or users without requiring permanent access keys.

For example, an EC2 instance can assume an IAM role to access an S3 bucket.

EC2
 ↓
IAM Role
 ↓
S3 Permissions
 ↓
S3 Bucket
EC2 Interview Questions
8. What is EC2?

Answer:

EC2 stands for Elastic Compute Cloud. It is an AWS compute service that provides virtual servers called instances. We can select the operating system, CPU, memory, storage, networking, and security configuration according to our requirements.

9. What is an EC2 instance?

Answer:

An EC2 instance is a virtual server running in AWS. We can use it to host applications, web servers, databases, or other workloads.

10. What is the difference between EC2 and S3?

Answer:

EC2 is a compute service used to run applications on virtual servers, whereas S3 is an object storage service used to store files and objects such as backups, images, logs, and documents.

Simple way:

EC2 → Compute
S3  → Storage
11. How do you connect to a Linux EC2 instance?

Answer:

Typically, I connect to a Linux EC2 instance using SSH. I need the instance's reachable IP or DNS, appropriate security-group rules, and the required private key.

Example:

ssh -i my-key.pem ec2-user@<public-ip>
VPC Interview Questions
12. What is a VPC?

Answer:

VPC stands for Virtual Private Cloud. It is a logically isolated virtual network in AWS where we launch resources such as EC2 instances. We can configure subnets, route tables, Internet Gateways, NAT Gateways, security groups, and network ACLs within the VPC.

13. What is a subnet?

Answer:

A subnet is a range of IP addresses within a VPC. We divide a VPC into multiple subnets to organize resources and control network connectivity.

Example:

VPC: 10.0.0.0/16

Web Subnet → 10.0.1.0/24
DB Subnet  → 10.0.2.0/24
14. What is the difference between public and private subnet?

Answer:

A public subnet has a route through an Internet Gateway, allowing resources with appropriate public connectivity to communicate with the internet. A private subnet does not have a direct route to the Internet Gateway.

Typical architecture:

Internet
   |
  IGW
   |
Public Subnet
   |
  EC2
   |
Private Subnet
   |
Database
15. What is an Internet Gateway?

Answer:

An Internet Gateway is a VPC component that enables communication between resources in a VPC and the internet, provided the appropriate routing and resource configuration are in place.

16. Is creating an Internet Gateway enough to make an EC2 instance public?

Answer:

No. Creating an Internet Gateway alone does not make an EC2 instance public. The subnet needs an appropriate route to the Internet Gateway, and the EC2 instance also needs suitable public connectivity and security-group rules.

17. What is a route table?

Answer:

A route table contains routing rules that determine where network traffic should be directed.

For example:

Destination       Target

0.0.0.0/0         Internet Gateway

This means traffic destined for external networks is routed through the Internet Gateway.

18. Can one route table be associated with multiple subnets?

Answer:

Yes. A route table can be associated with multiple subnets. However, each subnet has one main route table association at a time.

VPC Architecture Questions
19. How would you design a simple web application in a VPC?

Answer:

I would create a VPC and divide it into public and private subnets. Web or application servers can be placed in the public or appropriately routed application tier, while databases can be placed in private subnets. I would configure route tables, an Internet Gateway for public connectivity, security groups to control traffic, and a NAT Gateway if private resources require outbound internet access.

Example:

                 Internet
                    |
                   IGW
                    |
             Public Subnet
                    |
                   EC2
                    |
             Private Subnet
                    |
                  RDS
20. Why do we keep the database in a private subnet?

Answer:

The database generally doesn't need direct internet access. Keeping it in a private subnet reduces its exposure to the public internet. Access can instead be restricted to application servers through appropriate security-group rules.

VPC Peering Questions
21. What is VPC Peering?

Answer:

VPC Peering is a networking connection between two VPCs that allows resources in those VPCs to communicate using private IP addresses, subject to routing and security rules.

Example:

VPC-A                         VPC-B
10.0.0.0/16                  20.0.0.0/16
   |                            |
 EC2                          EC2
   \                            /
    \------ Peering -----------/
22. Is creating VPC Peering alone enough for communication?

Answer:

No. After creating the peering connection, we also need to add appropriate routes to the route tables of both VPCs and ensure security groups and network ACLs allow the required traffic.

This is a very common interview question.

23. Can two VPCs have overlapping CIDR ranges for VPC Peering?

Answer:

No. VPC Peering requires non-overlapping CIDR ranges because the routing needs to distinguish between the networks.

Example:

VPC-A → 10.0.0.0/16
VPC-B → 10.0.0.0/16

This creates an overlapping address space and cannot be used for normal VPC peering.

Scenario-Based Questions
24. Your EC2 instance cannot access the internet. What will you check?

Answer:

I would troubleshoot layer by layer:

Check whether the EC2 instance has appropriate public connectivity.
Check the subnet's route table.
Verify that 0.0.0.0/0 routes to the Internet Gateway for a public subnet.
Verify the Internet Gateway is attached to the VPC.
Check security-group outbound rules.
Check network ACL rules.
Check the instance's OS-level firewall and network configuration.
Verify DNS configuration if the issue is specifically with domain-name resolution.
25. EC2 is running but you cannot SSH into it. What will you check?

Answer:

I would check the EC2 instance status first. Then I would verify that the instance has appropriate network connectivity, the security group allows inbound SSH on port 22 from my source IP, the subnet routing is correct, and the Network ACL isn't blocking the traffic. I would also verify the SSH key, username, operating-system SSH service, and host-level firewall.

Example:

SSH
 |
Port 22
 |
Security Group
 |
Network ACL
 |
Route Table
 |
EC2
26. An application on EC2 needs to access S3. Would you store AWS access keys on the EC2 server?

Answer:

I would avoid storing long-term access keys on the EC2 server. Instead, I would attach an appropriate IAM role to the EC2 instance and grant the role only the required S3 permissions.

This is a strong DevOps interview answer because it demonstrates least privilege and secure credential management.
